Overview

SICA detects session hijacking by analysing client binding in HTTP server access logs. Rather than relying on passwords or tokens, SICA observes whether the network address and browser fingerprint associated with a session change in ways consistent with a session-replay attack. The system is passive; it requires only the access log entries that web servers already produce.

Detection Signals

User-Agent

Client Fingerprint

SICA parses the User-Agent header of every request to extract the browser family, major version, operating system, and device class. When a session's requests arrive from a different browser, OS, or device type, the agent score increases to 1.0. A version-only change (same browser, updated version) receives a partial score of ….

Network

Network Similarity

Each request's source IP is compared against the session's reference client. A completely different /16 network scores 1.0. A different /24 subnet within the same /16 scores …. A new address within the same /24 scores …. The same IP address scores 0.0.

Binding Fork

Binding Fork Detection

A binding fork occurs when a client that was seen earlier in a session re-appears after a different client has used the same session. This is the strongest indicator of session replay: the attacker has the session token, the legitimate client continues browsing, and the request pattern reveals the split.

Normal Client (A) → Request
Session continues normally
Different Client (B) → same session token
Original Client (A) returns → binding fork
